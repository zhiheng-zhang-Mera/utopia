# REX-803 Scenario Runner Implementation Plan

**Goal:** Run bounded controlled campaigns through the existing Research surface and canonical safe tasks.
**Spec:** Digital-City mission-book/research-strengthening/REX-803-scenario-runner-and-repetition-engine.md at claim commit 5baee25.
**Architecture:** File-backed campaign receipts reference canonical tasks; the runner never owns task execution state. A gateway adapter creates, observes and cancels existing safe tasks. Seeds come from the accepted manifest contract; restart interrupts rather than silently resumes.
**Tech stack:** Node 24, existing Gateway/Store/trace and vanilla Web UI. No new dependencies.

## Constraints and review focus

- Maximum 1000 measured runs, 100 warmups; run timeout 1..300000 ms; campaign wall bound <=3600000 ms.
- Refuse missing topology identities, unsupported scenario, mutable software identity and parallel campaigns on the same experiment.
- Timeout/cancel cancels only the campaign's own canonical task; retain every excluded receipt.
- Restart marks active receipts interrupted, cancels any owned pending task and never submits additional work.
- Stop conditions bound measured execution; warmups are excluded from success/failure measurements.
- Physical Alien/Mech/Android campaign and opposite-host review remain separate acceptance evidence.
