# Explicit PCF remote-worker candidate port

`remote-worker-port.mjs` is an opt-in canonical WBC worker-pool port. It does not start a server, discover hosts, create task or credential databases, enroll a worker, or activate Mech. The existing canonical Store owns all task, reservation, attempt, epoch, capsule and claim-nonce state.

API:

- `createRemoteWorkerPort({enabled, owner, taskFor, readAuthority, authorizeWorker, observations, artifacts, verifyClosed, validateAuthorityBoundary, requestStop?, now?})`: canonical `endpoints/dispatch/claim/report/control`, plus authenticated `workerStatus/input/processStarted/collect`.
- `dispatch({endpointRef, taskId, workload, idempotencyKey})`: requires an existing `pcf-v1` canonical task; verifies actual input artifact bytes; uses placement/admission/epoch claim; stores the capsule, exact device/boot/instance, input binding and holder on that task. Origin, action and session must match canonical ownership. Policy comes from injected existing owner authority with explicit trusted-fabric sharing consent; the bridge never adds devices or consent. Reservation limits are CPU 8 and memory 512 MiB per app, additionally constrained by injected observations.
- `claim({nodeId, principal})`: rechecks the current injected worker grant and owner policy; durably marks a one-use delivery nonce. Reconstructing the adapter does not allow a second delivery. Lost claim responses remain attention cases rather than automatic replay.
- `report({nodeId, taskId, principal, state, result})`: RUNNING is informational. Terminal reports require `result: {claimNonce, receipt, outputBase64}`. Capsule bindings, epoch, policy version, owned PID and independently injected trusted close proof must match. Actual decoded bytes must match the output digest; artifact publication is followed by fresh grant and policy checks before canonical commit. Legacy COMPLETED alone is never success. Failed reports preserve RUNNING reservations when stop is unknown.
- `control({nodeId, taskId, principal})`: persists stopRequested and calls the injected stop transport. It returns stopped=false and preserves RUNNING; transport timeout or acknowledgment is never proof of stopped execution.
- `createRemoteWorkerRequest({port, canonical=port, authenticate})`: adapts existing `createHeadlessAgent.runOne` node routes to the canonical pool. `authenticate(context)` must resolve the existing authenticated transport handle to a device/boot/instance principal every time. It does not issue credentials or trust body IDs. Register/heartbeat/descriptor only project injected current observations; sharing mutation is NOT_WIRED.
- `createRemoteCpuExecutor({port, principal, onClosed})`: fixed local CPU child-process candidate. `executeCpu.onStart` records ownership before stdin; only its actual close result supplies receipt bytes. `onClosed` connects trusted close evidence used by `verifyClosed`. Real remote transport must provide equivalent independently trusted evidence; a worker-supplied closed boolean alone is insufficient.

`createWorkerPoolBackend({enabled:true,canonical:port,...})` narrows these endpoints using the existing configured member refs and descriptors. It does not enable the production Gateway or install worker grants. Genuine cross-host worker-grant authentication, remote artifact transport, stop observation and Mech activation remain NOT_WIRED / NOT_RUN. After headless cancellation fences callbacks, a stopped attempt may require explicit canonical reconciliation because the headless agent skips its final report; the port preserves uncertainty rather than claiming cancellation.

Run `node --test tests/pcf-stagec-remote-worker.test.mjs` in the isolated candidate checkout. Tests use disposable canonical Stores, injected transport/authority and two actual local CPU processes. Evidence is `SIMULATED_TOPOLOGY+ACTUAL_LOCAL_PROCESSES`; logical worker names do not establish two physical hosts. RED/GREEN logs are `.runtime/pcf-stagec-remote-*`. Review and hand off this candidate in one batch for separately approved Mech verification; do not install, merge or run it against the existing City from these component tests.

Enabled configuration requires `validateAuthorityBoundary({workload, capsule, principal, policyVersion, grantVersion, phase})`. It must synchronously read the current owner and worker grant facts together from the existing authority and return exactly `true` only when both are currently authorized and their versions match. A Promise, missing callback, stale version or revoked fact is rejected. `authorizeWorker` must return its current integer `version` as well as exact authorized device/boot/instance bindings. The callback runs inside canonical owner transactions for admission/epoch claim, capsule persistence, delivery nonce, owned PID, final result commit and stop requests; it runs immediately before input, RUNNING status and result delivery after asynchronous reads. It cannot create an approval database or automatically grant authority. A real remote deployment remains NOT_WIRED until this same-transaction boundary is backed by its actual existing authority.
