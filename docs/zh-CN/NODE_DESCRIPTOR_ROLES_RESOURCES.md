# 节点角色 / 能力 / 资源描述符

DATE: 2026-10-05
STATUS: WBC-602 REVIEW_CORRECTION_PENDING_EXACT_CI

现在 City 节点由“它能做什么”描述，而不是由它跑在哪台机器上描述。`node-descriptor-v1` 契约给每个节点一份稳定
描述符：角色、它自己声明能力、已上报资源、当前可用性、健康状态，以及指向拥有它身份的 City 注册表的引用。未来的
调度器因此可以按能力、角色与资源选择执行端点，而不是去匹配主机名。

描述符是**只读投影**，不是落盘记录。它在被读取的那一刻由 canonical node 记录计算得出，因此一次心跳、一次共享
开关变化、一次新的 telemetry 采样都会立即反映出来，也不会在唯一真相旁边长出第二份会过期的副本。原始 node 列表
保持不变，描述符作为兄弟字段发布，所以完全不知道描述符的 surface 看到的东西与之前一模一样。

向后兼容是这份契约的目的，而不是它的让步。所有新字段都是可选的：在该契约出现之前写入的 node 记录会被翻译成
`EXECUTION_NODE` 这一 legacy 默认角色，并标注 `LEGACY_DEFAULT`，因此读者永远能区分“声明的角色”和“默认来的
角色”。缺失的测量是带原因的 `UNKNOWN`——绝不是 `0`，也绝不是 `unavailable`；任务要求引用了一个从未被测量的
资源时，得到的是“未判定”，而不是拒绝，因为“我们没测过”和“这台机器太小”是两个不同的答案。

City 当前的真实角色可以表达：每台已注册的 Windows 节点既是执行节点也是验证节点，Android 客户端是控制面。Android
不是 City 节点，也不会被注册成节点；它由单独的控制面描述符描述，其 `isExecutionResource` 为 false，并且契约会
拒绝任何给这种实体加上 `EXECUTION_NODE` 角色的尝试。任何能力或资源字段的组合都无法把控制面提升为 worker。

资源上报是节点关于自己的**声明**，永远不是权威。身份仍属于 City 自己的节点注册表，描述符携带的是引用而不是副本，
并且描述符不做任何决定：它只报告，并且明确说明这一点。

真实双机结果在不可用时仍保持 NOT_RUN；隔离的单机测试不能证明硬件性能，本任务既不要求也不假设真实 Workbench 或
GPU 池存在。

异机复核修正：缺少 GPU 或网络测量保持 UNKNOWN，不代表没有硬件或网络不可达；仅显式
supported:false 声明表示 UNSUPPORTED。平台不匹配与测得零个加速器分别报告，未知容量不作调度决定。
忙碌执行端根据规范任务记录显示 acceptingWork:false。入网时显式配置的执行/验证多角色通过验证后保存，
旧协议重连和重启会保留，不按主机名或 Windows 平台猜测验证角色。Android 仍为非执行控制端。
显式错误角色或需求数组返回类型化拒绝；省略字段的旧节点仍兼容。角色引用既有身份，不授予新权限。
