# 配对搜索与六位码连接修复

DATE: 2026-10-04
PAIR_STATUS: SYNCHRONIZED

Web 首次连接页和已连接的配对页均提供 Wi-Fi/mDNS 与蓝牙搜索。选择发现的城市设备后，输入它显示的六位配对码。未选择设备时，配对码连接当前网页所属的城市。邀请链接和请求批准加入的方式继续可用。

后台快照刷新保留配对输入框的原节点、焦点、未输入完的配对码和失败提示。离开页面再返回时，从内存恢复输入；不会把输入内容保存为持久凭据。连接其他设备时，通过 URL 片段切换到选中的设备页面，清除片段后再执行配对交换。切换失败后的重试仍校验选中的城市身份。错误码、过期或已使用、锁定、身份不一致和设备不可达分别提示。

搜索由 Gateway 执行，使用它所在电脑的网络和蓝牙适配器。Windows 蓝牙扫描读取 Android 已使用的 UUID/厂商广播定位信息，不依赖浏览器 Web Bluetooth。蓝牙负责发现局域网地址，配对和控制仍通过局域网 HTTP/WebSocket 连接。不支持的平台、蓝牙关闭和搜索故障会明确提示。mDNS 身份确认会检查广播中的多个地址，避免因多网卡中的第一个地址不可达而丢弃整个设备。

验证范围：

- 配对、加入、邀请链接和双语界面专项测试的最终数量与源码哈希见 `evidence/raw/pairing-search/validation.json`。
- Windows 实际非回环网卡：发现三个可访问的 mDNS 城市端点，包含本次启动的 Gateway；六位码交换成功且会话被单次消费。
- Windows 实际蓝牙扫描：正常完成，但未收到 Utopia 定位广播。两台实体蓝牙设备的发现与配对：**NOT_RUN**。
- 中文界面截图使用脚本提供的附近设备条目，用于检查布局，不代表发现了第二台实体设备。见 `evidence/raw/pairing-search/web-zh.png`。
- 实测记录在 `evidence/raw/pairing-search/hardware-probe.json`，不包含配对秘密或凭据。

从当前功能分支工作区重启 Gateway，再刷新 Web 页面，即可加载修改。仅绑定 `127.0.0.1` 的 Gateway 无法接受其他设备的局域网连接，请使用常规 Utopia 启动器或配置实际局域网 IPv4 地址。本次测试电脑的有效非回环连接为以太网，因此两台实体设备同 Wi-Fi 验收为 **NOT_RUN**。
