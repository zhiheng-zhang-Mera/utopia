# Local controlled CPU study (PCF-707 / PCF-721)

`node scripts/pcf-research-local-study.mjs <frozen-config.json> <output-directory>` freezes a detached configuration and writes a unique manifest, canonical City SQLite store, artifacts, existing REX EventRecord trace and report per run. Reusing a directory creates another run; it never replaces earlier failed trials.

Configuration: version 1, id, repetitions (1–1000), stopAfterMs (1–3600000), exact 40-character softwareSha, workloads `["cpu-sort","cpu-sum"]`, nonempty hypotheses, evidenceClass `ACTUAL_LOCAL_CPU`, inputs keyed by those workloads with numeric `values` arrays, controls with hardware/cache/network descriptions, analysis `DESCRIPTIVE_ONLY`, failureCounting `KEEP_ALL`. Declare uncontrolled cache and hardware honestly. Before execution, the runner observes actual checkout HEAD and clean state and requires softwareSha to match. The production CLI refuses a dirty checkout. Component callers may explicitly set allowDirtySnapshot=true; the manifest/report then records DIRTY_COMPONENT_SNAPSHOT with bounded per-file SHA256 hashes and frozenSource=false. In that mode REX records actual implementationSha but omits softwareSha, so a dirty run cannot masquerade as a frozen clean source. Source identity is checked again after execution and drift becomes an infrastructure failure. The input digest, manifest digest and canonical task/action/process/output references bind each retained trial.

Trials use createFabricService and its actual approved local CPU subprocesses, canonical task/action records, policy checks and artifact/result consumption. Repetitions are sequential. Deadline and stopping limit bound subsequent submissions; all remaining planned trials become NOT_RUN. Refusals, failures and incomplete terminal states remain in the report. Descriptive latency includes submission, dispatch, collection and acknowledgement; completed-only latency always carries its sample count alongside failures. No inferential significance or improvement claim is produced.

`comparePolicies` is a pure COUNTERFACTUAL_SIMULATION. FIXED, CAPABILITY, LOAD and COMPOSITE all reuse planPlacement and its identical feasibility/authority shield. Its cost-ranking ablation uses CAPABILITY and cannot dispatch. Inputs must provide the existing workload, candidate and policy contracts; this helper does not invent hardware observations or execute a baseline benchmark.

The research adapter captures canonical events through the existing REX collector. Reopening that collector verifies persisted raw/context/normalized EventRecord equality. `trace.replayValidated` means trace reconstruction only; it does not claim REX805 campaign execution replay. Missing metrics and experiment fields remain the collector's PARTIAL/NOT_OBSERVABLE. Bounded collector drops, retention and storage errors remain visible; CLI returns nonzero for observed failures or invalid trace reconstruction. Raw source data remains canonical, never a parallel trace schema.

Validation: `node --test tests/pcf721-study.test.mjs`. RED/GREEN evidence: `.runtime/pcf-stagec-study-red.log` and `.runtime/pcf-stagec-study-green.log`. Local contract tests execute two CPU software workloads and retain authorization refusals. This is scoped local development, not completion of PCF-721 research acceptance.

One consolidated Mech verification remains required: independently rebuild the exact source/config/input identities, execute and export the same study, compare retained failure and replay evidence, and record actual hardware/cache/network controls and clock skew. Mech independent rebuild, cross-host acceptance, REX runner/fault/campaign replay/export integration, mixed engineering/ML workloads, SLO/recovery/observer overhead, and statistical benefit remain NOT_RUN. No genuine Codex engineering executor, ML training, dual-host, physical-device or HA PASS is claimed.

All planned samples are initialized before infrastructure setup. Store/setup/start/events/trace/cleanup failures retain completed trials, mark unstarted samples NOT_RUN, and appear in infrastructureFailures. Each cleanup is guarded independently. A report write failure throws STUDY_REPORT_WRITE_FAILED with the recoverable ledger in error.report; the CLI prints recoveryLedger and returns nonzero. R1 source/infra regression logs: .runtime/pcf-stagec-study-r1-red.log and .runtime/pcf-stagec-study-r1-green.log.

Source snapshots include all paths changed from HEAD (staged and unstaged), untracked paths, and a bounded SHA256 digest of the staged binary diff. Index-only changes therefore alter identity even if porcelain status or working-tree contents are unchanged. The regression fixture uses a separate temporary Git repository and never stages the implementation checkout.
