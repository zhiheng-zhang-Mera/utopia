# Engineering runtime candidate (PCF-727/728)

This is one local candidate to hand to Mech for combined verification. It does not activate parked workbooks or install a tool in an arbitrary existing Codex session. It reuses `bindEngineeringExecutor` and the ConnectorPort method inventory. `createEngineeringTools` requires an injected canonical service implementing submit, inspect, cancel, collect and acknowledge; that service remains responsible for current task ownership, single terminal state, idempotency and result digest validation. Each facade invocation rechecks caller authorization. Collect and acknowledge remain separate calls.

Installed CLI evidence is retained in `.runtime/pcf-stagec-engineering-cli-help.log`. `codex exec --help` advertises JSONL stdout, stdin prompts, explicit working directory, workspace-write sandbox and ignore-user-config. `codex exec resume --help` advertises explicit session IDs and latest-session selection. This candidate deliberately declines resume: no durable ownership ledger or restart reconciliation exists. It never uses `--last` or attaches an ambient session. Backend session binding comes only from a `thread.started` event on a process this runtime created.

Production submission requires explicit approval, external auth readiness and an isolated CODEX_HOME configured without reading credentials. No ambient provider keys are inherited. The default validator requires a clean linked Git worktree at the exact base SHA. Dirty snapshots, content staging, artifact digests and canonical epoch/lease fencing must be provided by the surrounding approved execution pipeline. This module must not be used as a replacement scheduler. It returns no automatic merge or workspace overwrite.

Submit synchronously copies and freezes caller input before awaiting validation. The validator returns the canonical real path and verified SHA; argv, spawn cwd and evidence use that immutable result. Custom validators and fixture argv are restricted to explicit component fixtures using the current Node executable. Successful process exit still carries `unknownSideEffects=true`: child exit cannot prove tree termination or reconcile engineering side effects. The mutation regression's RED/GREEN evidence is in `.runtime/pcf-stagec-engineering-mutation-{red,green}.log`.

Durability regression evidence is in `.runtime/pcf-stagec-engineering-durable-{red,green}.log`. The final 14-test run is `.runtime/pcf-stagec-engineering-canonical-final.log`. `pcf728-canonical-flow.test.mjs` exercises a real canonical SQLite Store, admission, attempt ownership, capsule validation, process ownership persistence, output artifacts, committed receipt and caller collect/ack. A real Node subprocess produces 42; the same authorized caller reads it and uses 43 as the next explicit input. This is COMPONENT_FIXTURE evidence, not a real Codex or cross-host caller integration.

Owner callbacks have an independent `callbackTimeoutMs` deadline (default 5 seconds, maximum 60 seconds). Callback timeout is ATTENTION; collection stays refused. Each callback receives a second argument with AbortSignal, fenceId, ownership refs and `isCurrent()`. The trusted canonical owner must check that fence immediately before each atomic ownership/receipt write, including after awaits. Runtime cannot cancel an arbitrary injected promise or undo its writes. A callback that ignores its fence can still write late outside this module; that is an owner integration error, not a claimed cancellation guarantee. Late promise settlement cannot change runtime terminal state or permit collection. Never-settling/late promise RED/GREEN evidence is retained in `.runtime/pcf-stagec-engineering-owner-timeout-{red,green}.log`.

The runtime fixes argv, disables shell execution, bounds stdout plus stderr bytes, event count, session count and wall-clock duration. It records PID, host/boot supplied by the approved host adapter, task/attempt/base/worktree, exit code, signal and process close. Cancel requests termination of its own child; it does not claim process-tree termination or absence of unknown effects. Windows descendants may survive a child kill: `processTreeTermination=NOT_PROVEN`. A completed JSONL turn plus zero exit and an observed owned session are required for component success. Malformed/truncated JSONL, overflow, timeout and nonzero exit cannot become success. Sessions/handles are memory-only: restart recovery is UNSUPPORTED. Production requires trusted async onStart and persistReceipt callbacks to the external canonical owner. PID/task/attempt/host ownership is persisted before stdin delivery; start refusal kills and waits for close. Collection requires the bounded exit receipt to be persisted; receipt write failure is ATTENTION. No second task database is created.

RED and GREEN outputs are `.runtime/pcf-stagec-engineering-red.log` and `.runtime/pcf-stagec-engineering-green.log`. The tests run real Node subprocess conformance fixtures, with an explicitly injected component workspace validator. They are not real Codex inference. CODEX_LOCAL, CODEX_REMOTE, DEEPSEEK_LOCAL, DEEPSEEK_REMOTE, real-provider cancellation/restart, same-parent caller consumption and opposite-host Formal Review all remain NOT_RUN. Mech must verify the whole candidate once with canonical refs, approved input staging, host/boot/attempt, version, digests, actual caller tools and cancellation/side-effect reconciliation before any product claim.
