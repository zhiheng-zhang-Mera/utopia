# City 多主机成员、设备列表与资源共享：调查及设计草案

日期：2026-10-04
状态：用户已要求开始修复。每台主机初始是自己的主城；加入成功仅降级本机，目标主城不受影响。名称与角色不得固定 Alien。
代码基线：48cbc21376007c5461e8e456a898c3f788f0fa77。

## 已确认的原因

1. Web 的 nodeRows 只读取 city.nodes。控制端连接存在 controlSurfaces，设备注册存在 devices/installations，两者没有进入设备列表。
2. 远程入网的 launcher 保存身份或打开远端浏览器后直接返回，没有启动本机 agent。只有 Gateway 生产入口启动 agent。
3. reference-node 默认 id=alien-reference-node、displayName=Alien-PC，未使用本机稳定身份和入网名称。
4. enrollment 的 writeDevice 使用 dev:deviceId 存储，readDevice 却按裸 deviceId 查找。真实入网后 describe 返回的 displayName 为 null。
5. node 路由只接受共享 nodeToken；已入网会话不能以自己的身份注册本机 worker。无需也不应向每个设备复制主城的 nodeToken。
6. 现有 relay 只承载入网握手及会话请求，没有成员之间的普通通信入口。
7. 浏览器入网审批 exchange 返回主城 control credential，不创建成员设备记录；需要把新客户端入网改为成员身份，而不能仅改变列表渲染。

## 当前观察与复现

生产 City 的 nodes 只有 alien-reference-node / Alien-PC；同时有两个 Web 控制端连接。这是实际数据模型和渲染的差异，不能根据两条 Web 连接推断是两台物理主机。

隔离 Gateway 中使用真实六位短码登记“入网主机 B”，再打开其会话：cityId 匹配；snapshot.nodes 长度为 0；enrolledDevice.displayName 为 null；以成员会话调用 node/register 返回 401。没有改动生产凭据、城市名称或任务。

## 目标与选定方案

保持一台主机最多运行一个 City Gateway。一座 City 包含多个成员主机；加入的设备连接该 City 并运行本机成员代理，不再另建 Gateway。采用 City 中转通信和现有任务调度；首期不要求设备互相开放入站端口，不新建 P2P 网络。

### 统一成员身份及列表

修复注册记录索引；将本机稳定 deviceId、安装身份、入网名称、控制端在线状态和 worker 关联起来。新审批/短码入网统一登记成员。主城计算代理使用主机稳定身份，显示名称不再固定 Alien。历史运行节点保留兼容映射，避免产生第二个本机条目。

快照增加统一成员视图与当前请求者的身份。计算节点保持现有接口兼容。列表按当前请求者置顶“本机 · 入网名称”，然后显示同一 City 的其他成员。标明“城市主机/成员主机/仅 Web 控制端”、在线状态、计算代理状态和已共享能力。不同浏览器标签页合并为同一已验证设备；纯浏览器使用控制端身份，不能猜测属于主城物理主机。其他成员的离线记录仍保留。

### 本机成员代理

加入远程 City 后启动受本机锁约束的成员代理，并在后续启动中复用；每个本机成员代理仅服务当前所选 City。代理使用自身注册身份换取可刷新、有时限的会话；服务端将 node 操作绑定到该身份，只允许更新自己的注册、心跳、任务领取和结果。撤销后停止领取工作并清理在线状态。重连恢复同一 deviceId，不能覆盖其他成员。

Web 单独打开只承担控制和通信。浏览器不能启动任意本机进程或承诺共享硬件；使用安装版启动器接入本机代理，并在界面明确显示是否已连接计算代理。

### 成员互相通信

新增成员消息服务，由 City 验证发送者和目标成员、持久记录有界消息并通知事件流。允许成员在设备详情中发送消息、查看对方发来的消息和确认接收。身份来自认证会话，消息不能自行声明发送者；隔离其他 City、拒绝已撤销成员；离线目标显示等待接收。支持重连查询和去重，不能把服务器收到消息说成设备已收到。

### 共享硬件计算资源

安装版成员代理上报本机 CPU/内存及已实现能力，复用现有任务调度和严格目标绑定。提供“共享本机计算资源”开关及状态。开启后可选择另一个在线且已共享设备执行现有安全任务，结果回到同一 City，各成员均能查看。关闭共享、代理离线或身份撤销后禁止继续领取。浏览器和未提供真实遥测的设备显示“未提供”，不能伪造硬件指标。

首期资源共享以现有安全计算/临时文件任务为实际实现能力。GPU、任意 shell、AI 模型服务需各自能力适配器和验证，不能因设备在线就标为支持。资源统计只累计在线且共享开启、遥测新鲜的代理。

## 实施与验收

1. 为索引错误、列表遗漏和会话不能注册编写失败复现，再修复统一身份与快照。
2. 实现安装版成员代理生命周期和绑定身份的 node 授权；验证多安装启动只保留一个代理，保留一个 Gateway 的约束。
3. 实现成员消息及设备列表/详情：分别以 A、B、C 身份验证“本机”置顶、入网名称和完整成员列表。
4. 用 A/B 两个独立运行代理在同一 City 验证双向消息接收、B 指定计算任务、B 遥测和结果回传；确认任务实际由 B 的进程执行。
5. 验证重复标签页、同名成员、重启、断线、身份撤销、跨 City 冒充、停止共享及目标离线；不把模拟测试当作物理跨主机实测。
6. 更新本机实际安装，完成现有 Gateway/Web、City、Android 和 CI 回归，保留失败与未运行项目；在特性分支提交 PR。

实际双物理主机的实测仍需要可用的第二台设备；当前仅观察到一台主机环境。该部分不足时记录 NOT_RUN，不声称已经验证。
